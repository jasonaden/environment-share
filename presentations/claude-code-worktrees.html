The Problem

01 // Context Switching

Why Development
Flow Breaks

Every branch switch is a context switch. Your brain pays the price.

  • Dirty working trees
    Uncommitted changes block branch switches. You stash, forget, and lose work.
  • Single checkout bottleneck
    One repo, one branch at a time. Parallel tasks? Wait your turn.
  • Agent collisions
    Multiple Claude sessions editing the same files leads to conflicts and overwrites.

02 // The Solution

What Are Worktrees?

An isolated copy of your repo with its own branch — created in seconds, cleaned up automatically.

Concept

03 // How It Works

One Repo,
Many Worktrees

Each worktree is a full working directory with its own branch. Changes in one don't touch the others.

  • Created at .claude/worktrees/<name>
  • Auto-branches as worktree-<name>
  • Shares git history — no cloning
  • Independent node_modules, build state
my-project/                  # main working tree
  .claude/
    worktrees/
      feature-auth/            # worktree 1
        src/
        package.json
      bugfix-123/              # worktree 2
        src/
        package.json
      do-the-thing/            # worktree 3
        src/
        package.json

04 // Commands

Start a Worktree

$ claude --worktree feature-auth Named worktree
$ claude -w bugfix-123 Shorthand flag
$ claude --worktree Auto-generated name
$ claude --resume feature-auth Resume later 
# Terminal 1 — feature work
claude -w feature-auth

# Terminal 2 — bug fix
claude -w bugfix-123

# Both run in parallel,
# zero conflicts
Features

05 // Capabilities

What You Get

Automatic Branching

Each worktree gets its own branch — worktree-<name> — forked from your default remote branch.

Smart Cleanup

No changes? Auto-removed on exit. Made commits? Claude asks if you want to keep or discard.

Resume Sessions

Pick up where you left off with claude --resume. Your worktree and branch are waiting.

Subagent Isolation

Spawn agents with isolation: "worktree" so each works on its own copy. Cleaned up automatically.

Management

08 // Manage

Worktree Housekeeping

$ git worktree list List all worktrees
$ git worktree remove .claude/worktrees/name Remove one
$ git worktree prune Clean stale refs
$ claude --resume feature-auth Resume a session

Tip

Add .claude/worktrees/ to your .gitignore to keep worktree contents out of your main repo's untracked files.

Remember

Run npm install in new worktrees — node_modules aren't shared between them.

Agent Teams

09 // --tmux Flag

Split-Pane
Agent Teams

Claude's --tmux flag spawns parallel agent teammates — each in its own tmux pane and worktree. Watch them all work simultaneously.

  • One pane per teammate — all visible at once
  • Each agent gets its own isolated worktree
  • Click any pane to interact directly
  • Works with native iTerm2 splits too

Setup

10 // Configuration

Enable Split Panes

$ claude --teammate-mode tmux Per-session
$ claude -w feature --teammate-mode tmux Worktree + tmux

Or set it permanently in settings.json:

{
  "teammateMode": "tmux"
}

Teammate modes:

  • tmux — split panes (tmux or iTerm2)
  • in-process — single terminal, Shift+Down to cycle
  • auto — detects your environment

How it works

Ask Claude to create a team. It spawns teammates as separate processes — each in its own tmux pane and worktree. A shared task list coordinates the work. When the team finishes, worktrees and panes clean up automatically.

Navigation

  • Click a pane to interact with that agent
  • Shift+Down to cycle (in-process)
  • Ctrl+T to toggle task list
